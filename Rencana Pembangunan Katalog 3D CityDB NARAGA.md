# Rencana Pembangunan Katalog 3D CityDB NARAGA

Oct 3, 2026 · @Fairuz Akmal Pradana

## Ringkasan dan keputusan

Katalog 3D dibangun di atas 3DCityDB v5 dengan data CityGML 2.0 diimpor apa adanya (opsi A), sehingga LOD 1 sampai LOD 4 tersimpan tanpa konversi ke CityGML 3.0 dan frontend Cesium dapat memanggilnya lewat API sebelum checkpoint 13 Okt 2026.

| Keputusan | Pilihan | Alasan |
| --- | --- | --- |
| Versi database | 3DCityDB v5 di PostgreSQL/PostGIS | v5 aktif dikembangkan; v4 kini hanya dalam mode perawatan |
| Penanganan LOD 4 | Opsi A: impor CityGML 2.0 tanpa opsi upgrade, ekspor tetap 2.0 | v5 menjamin data tidak hilang selama versi CityGML saat impor dan ekspor sama |
| Label LOD | Kolom `lod` (1-4) di katalog, terpisah dari skema 3DCityDB | Frontend tidak bergantung pada cara v5 menyimpan interior |
| Penyajian ke frontend | API katalog mengembalikan metadata dan ID aset Cesium ION; tile dilayani Cesium ION | Sesuai jalur Cesium ION pada flowchart |
| Arti "DDD" | Domain-Driven Design versi ringkas | Asumsi; bila yang dimaksud Database Design Document, lebur ke bagian Skema |

Uji round-trip satu sampel LOD 4 pada 3 Okt memverifikasi opsi A. Bila gagal, cadangannya 3DCityDB v4.

Sumber: [Compatibility and data migration, dokumentasi 3DCityDB v5](https://docs.3dcitydb.org/1.2/compatibility/) dan [rilis 3DCityDB](https://github.com/3dcitydb/3dcitydb/releases).

## Rancangan awal ERD

&#91;embedded content: ERD konseptual · 5 tabel katalog dan 1 tabel 3DCityDB\]

Satu dataset memiliki banyak layer, satu level LOD dipakai banyak layer, dan tiap layer punya tileset serta catatan impor. Tautan ke objek 3DCityDB sengaja dibiarkan putus-putus sampai keputusan di ERD 3 Okt.

## Rencana DDD

Domain dipecah menjadi tiga bounded context agar metadata katalog tidak bercampur dengan model kota semantik dan alur publikasi tile.

| Context | Tanggung jawab | Penyimpanan |
| --- | --- | --- |
| Katalog | Mendaftarkan dataset, layer per LOD, status, dan tileset; melayani frontend | Schema `catalog` |
| Model Kota | Menyimpan objek kota semantik CityGML (bangunan, bagian, permukaan) | Schema `citydb` (3DCityDB v5) |
| Publikasi Tile | Mengonversi ke 3D Tiles (`convertwin`) dan mengunggah ke Cesium ION | Berkas keluaran dan Cesium ION |

**Bahasa bersama**

| Istilah | Arti |
| --- | --- |
| Dataset | Kumpulan data satu wilayah dari satu sumber, misalnya OIKN atau IKN generated by NARAGA |
| Layer | Dataset pada satu LOD dan satu versi; unit yang dipilih frontend |
| Tileset | Hasil 3D Tiles dari sebuah layer, di Cesium ION atau host sendiri |
| LOD | Tingkat detail 1 sampai 4 menurut CityGML 2.0 |
| Status | Tahap layer: draft, importing, validated, converted, published, deprecated, failed |

**Aggregate dan aturan invarian**

- Dataset adalah aggregate root; layer dan tileset hanya berubah lewat dataset.
- Kombinasi dataset, LOD, dan versi bersifat unik.
- Layer baru boleh dipublikasikan setelah impor berstatus `validated`.
- Layer berstatus `published` wajib punya minimal satu tileset aktif.
- Nilai LOD hanya 1 sampai 4.

## Rencana skema database

Skema katalog hidup di schema `catalog` yang terpisah dari `citydb`, sehingga tabel 3DCityDB v5 tidak diubah dan upgrade 3DCityDB tidak merusak katalog.

| Tabel | Fungsi | Kolom kunci | Constraint dan indeks |
| --- | --- | --- | --- |
| `dataset` | Sumber data per wilayah | `id`, `code`, `name`, `region`, `source_system`, `generated_by`, `crs_epsg`, `bbox` | `code` unik; GiST pada `bbox` |
| `lod_level` | Referensi LOD | `lod`, `name`, `description` | CHECK `lod` antara 1 dan 4; diisi 1-4 |
| `layer` | Dataset pada satu LOD dan versi | `id`, `dataset_id`, `lod`, `version`, `status`, `source_citygml_version`, `feature_count`, `bbox` | Unik (`dataset_id`, `lod`, `version`); indeks (`lod`, `status`); GiST pada `bbox` |
| `tileset` | Hasil 3D Tiles sebuah layer | `id`, `layer_id`, `provider`, `ion_asset_id`, `url`, `converter_version`, `is_active`, `published_at` | `ion_asset_id` wajib bila provider `cesium_ion`; maksimal satu tileset aktif per layer |
| `import_job` | Jejak impor ke 3DCityDB | `id`, `layer_id`, `tool`, `tool_version`, `status`, `started_at`, `finished_at`, `report` | Indeks pada `layer_id` |

**Konvensi**

- Primary key UUID, nama snake\_case, waktu bertipe `timestamptz`
- `bbox` disimpan di EPSG:4326 untuk filter API; CRS asli data dicatat di `crs_epsg`
- LOD 4 disimpan sebagai `lod = 4` dengan `source_citygml_version = '2.0'`, tanpa opsi upgrade
- `generated_by` pada `dataset` (misalnya `external` atau `naraga`) membuat layer LOD 2 hasil NARAGA masuk tanpa perubahan struktur
- Migrasi berurutan lewat satu alat migrasi yang cocok dengan stack API, dapat dijalankan dari database kosong, dan menanam data awal (`lod_level` 1-4, dataset OIKN)

**Keputusan terbuka untuk ERD (3 Okt):** cara mengikat objek 3DCityDB ke layer. Opsi: tabel penghubung `layer_feature` yang eksplisit tetapi besar bila objeknya jutaan; satu schema 3DCityDB per dataset; atau penandaan lewat identifier saat impor. Nama tabel dan kolom 3DCityDB v5 (misalnya `citydb.feature`) diverifikasi langsung pada instance sebelum ERD dikunci.

## Kerangka SAD

&#91;embedded content: Arsitektur dan alur data · 7 komponen, 1 instance database\]

Data LOD 1 masuk ke 3DCityDB lewat `citydb-tool` dan ke Cesium ION lewat `convertwin`; ID aset dicatat di katalog, sehingga frontend hanya perlu satu panggilan ke API. SAD v1.0 (3-5 halaman) memuat:

1. Tujuan, ruang lingkup, dan pemangku kepentingan
2. Kebutuhan fungsional dan non-fungsional, termasuk target waktu respons API
3. View komponen (diagram di atas) dan tanggung jawab tiap komponen
4. View deployment: Docker Compose untuk pengembangan dan checkpoint; hosting produksi dikonfirmasi tim DevOps
5. Alur data: impor, konversi, publikasi, pencatatan, penyajian
6. Catatan keputusan arsitektur (ADR): v5 dan opsi A, label LOD terpisah, tile di Cesium ION, cara menautkan objek ke layer
7. Keamanan dan akses: CORS, token Cesium ION, rencana token NARAGA
8. Risiko dan hal yang ditunda

## Kontrak API untuk frontend

Frontend cukup memanggil satu endpoint katalog dengan parameter `lod`, lalu memuat tileset dari ID aset yang dikembalikan.

| Endpoint (read-only, `/api/v1`) | Fungsi |
| --- | --- |
| `GET /catalog?lod=1&bbox=minx,miny,maxx,maxy&status=published` | Daftar layer yang cocok, tiap item membawa tileset aktifnya |
| `GET /layers/{id}/tileset` | Tileset aktif sebuah layer |
| `GET /datasets` dan `GET /datasets/{id}` | Daftar dataset dan detailnya beserta layer per LOD |
| `GET /health` | Status layanan dan koneksi database |

Aturan: `bbox` berupa lon/lat EPSG:4326; `lod` bernilai 1 sampai 4 dan bila dikosongkan berarti semua level; `status` bawaannya `published`; paginasi lewat `limit` dan `offset`; kesalahan memakai satu format JSON baku. Pada checkpoint API belum memakai autentikasi dan dibatasi lewat CORS ke domain frontend; token NARAGA ditambahkan di Fase 4.

Contoh respons (nilai ilustrasi):

```json
{
  "items": [
    {
      "layerId": "b6f1c2d4-0000-0000-0000-000000000001",
      "dataset": { "code": "oikn", "name": "OIKN", "generatedBy": "external" },
      "lod": 1,
      "version": 1,
      "status": "published",
      "bbox": [116.6, -1.0, 116.9, -0.8],
      "tileset": { "provider": "cesium_ion", "ionAssetId": 123456, "url": null }
    }
  ],
  "limit": 50,
  "offset": 0,
  "total": 1
}
```

Pemakaian di Cesium Canvas:

```js
const res = await fetch(`${API}/catalog?lod=${lod}&status=published`);
const { items } = await res.json();
const tileset = await Cesium.Cesium3DTileset.fromIonAssetId(items[0].tileset.ionAssetId);
viewer.scene.primitives.add(tileset);
```

Token Cesium ION berada di konfigurasi frontend dan dibatasi untuk membaca aset yang dipakai saja; API tidak menyimpan token tersebut.

## Pengujian dan risiko

Lima uji menentukan apakah katalog layak dipakai frontend; uji round-trip LOD 4 dilakukan pertama karena hasilnya menentukan opsi A atau cadangan v4.

| Uji | Cara | Lulus bila |
| --- | --- | --- |
| Round-trip LOD 4 | Impor sampel CityGML 2.0 ber-LOD 4, ekspor kembali, bandingkan | Jumlah objek, ruang interior, dan geometri sama |
| Migrasi | Jalankan dua kali dari database kosong | Berhasil dan tidak menggandakan data awal |
| Impor LOD 1 | Bandingkan jumlah feature sumber dan database; cek validitas geometri dengan `ST_IsValid` | Jumlah sama; geometri tidak valid tercatat di `import_job` |
| API | Tes otomatis untuk filter `lod`, `bbox`, `status`, paginasi, dan format kesalahan | Semua kasus lulus |
| Integrasi frontend | Ganti nilai `lod` di Canvas | Tileset yang tepat termuat tanpa konfigurasi statis |

Target waktu respons API ditetapkan tim saat menyusun SAD.

**Risiko utama**

- Uji LOD 4 gagal: pindah ke 3DCityDB v4, dengan biaya sekitar satu hari ulang setup. Karena itu uji dilakukan pada 3 Okt.
- Data LOD 1 belum siap pada 6 Okt: jalur kritis; majukan impor bila selesai lebih awal dan batasi Canvas pada fungsi dasar.
- Cara menautkan objek 3DCityDB ke layer terlambat diputuskan: kunci pada ERD 3 Okt agar skema tidak berubah setelah impor.
- Nama tabel 3DCityDB v5 berbeda dari asumsi: verifikasi pada instance sebelum ERD dikunci.
- Kuota akun Cesium ION: cek kapasitas penyimpanan dan jumlah aset sebelum unggah 9 Okt.
